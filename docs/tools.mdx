# Built-in Tools

The worker sees a deliberately tiny toolset. Every tool is bounded, and
only three can mutate anything.

## Free tools (read-only, never gated)

| Tool | What it does |
|---|---|
| `read_file` | Reads a file through the path sandbox, capped at `worker_read_lines` lines |
| `grep` | Regex search across the worktree; results truncated |
| `glob` | Path-pattern search |
| `list` | Directory listing |
| `diagnostics` | Compiles-focused quick feedback (opt-in per build) |
| `web_fetch` | Fetches a URL, fenced as untrusted context (`allow_web` only) |
| `subagent` | Spawns a read-only explorer with `read/grep/glob/report` only (`allow_subagent` only) |

Re-reading an unchanged file inside one attempt is answered from cache
without consuming the action budget — the model is told to do something
new.

## Mutating tools (intercepted)

| Tool | What it does | Deterministic gate |
|---|---|---|
| `write_file` | Creates or overwrites a file | Path sandbox: `..`, absolute, symlink, and sibling-prefix escapes rejected; must fall under the step's `allowed_paths` |
| `edit_file` | Exact-match string replacement | Same path rules |
| `run_command` | Shell command in the worktree | Blocklist check; read-only commands (tests, ls, grep...) run free, mutating ones are loop-checked |

An exact repeat of a failed mutating action is rejected by
fingerprint ("loop detected"), forcing a different approach.

## Terminal tool

`finish_step` — the worker declares the step complete with a summary
stating how each invariant holds. This triggers the deterministic
verification command and then AiWrangler's check gate, which reads that
summary and checks it against the actual diff.

## What is deliberately absent

No arbitrary shell, no network by default, no git access, no tool that
can escape the worktree, and no `todo` tool — small models fixate on
updating todo lists instead of editing code, so planning context is
provided by the governor instead.
