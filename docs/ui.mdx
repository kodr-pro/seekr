# User Interface

seekr ships a TUI for interactive runs and a headless JSONL mode for
scripting.

## The TUI flow

1. **Goal intake** — describe what you want built.
2. **Clarify** — answer the planner's bounded questions.
3. **Plan review** — inspect the DAG (steps, invariants, allowed paths,
   verification commands) before it grinds.
4. **Grind dashboard** — the run in progress:
   - tree-style DAG panel with per-step status
   - progress gauge and live gate verdicts (`🛡 aiwrangler [check] …`)
   - per-tier token share gauges (worker / gates / frontier)
   - scrollable activity log (actions, approvals, rejections,
     rollbacks, escalations)

## Keys

| Key | Action |
|---|---|
| `?` | help, anywhere |
| `Ctrl+G` | control center |
| `Ctrl+C` twice | quit (the run is resumable) |

## Control center (`Ctrl+G`)

- **Runs** — browse every run, attach to a live one, resume, merge, or
  clean it.
- **Providers** — CRUD with live key tests; assign the worker and
  frontier roles.
- **Settings** — the `[jj]` block: attempts, timeouts, budgets,
  `wrangler_timeout_secs`, `allow_degraded`.
- **Keys** — quick reference for the whole TUI.

## Headless / JSON

```bash
seekr run . --goal "..." --headless          # human-readable progress
seekr run . --goal "..." --headless --json   # one JSON event per line
```

The JSON stream is the governor's event log: `run_started`,
`wrangler_gate`, `step_started`, `action_proposed`, `action_rejected`,
`verification_failed`, `rolled_back`, `escalated`, `step_completed`,
`usage`, `run_completed`... Filter with `jq`:

```bash
... | jq -c 'select(.type=="wrangler_gate")'
... | jq -c 'select(.type=="step_completed") | .step_id'
```

The same events persist per run — `seekr logs <run-id>` replays them.

## The summary view

`seekr summary <run-id>` is the return-after-hours surface — designed
so a long absence never becomes an endless scroll:

- **needs attention** (top, capped): human-review parks, failed steps
  with a one-line why, review-severity finding counts, and an
  `unfinished` marker for runs whose process died.
- **steps**: one line each — status, attempts, and *who finished it*
  (worker or frontier).
- **findings (review notes)**: the gate's citable findings; the same
  notes fold into the merge commit via `seekr merge`.
- `--verbose` appends the raw event tail for debugging.
