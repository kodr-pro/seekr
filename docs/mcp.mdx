# AiWrangler Integration

seekr's semantic governance is
[AiWrangler](https://github.com/kodr-pro/AiWrangler) — ground-truth
guardrails for coding agents — consumed as a stdio MCP server. seekr
spawns the server once per run and drives its gate lifecycle; there is
no gate logic inside seekr to drift from the product.

## Lifecycle mapping

| seekr moment | AiWrangler tool | Verdicts seekr acts on |
|---|---|---|
| Run start | `wrangler_config` | health check (doctor + fail-closed spawn) |
| After DAG planning | `wrangler_plan` | PASS / CLARIFY / HUMAN + context pack |
| Step completion | `wrangler_check` | PASS / FIX REQUIRED / HUMAN REVIEW / DEGRADED |
| Owner intervention | `wrangler_ack` | pending findings list / recorded acknowledgments |
| Owner intervention | `wrangler_loop_reset` | circuit-breaker reset |

The context pack from the plan gate becomes the `GROUND TRUTH` block in
every worker prompt. The check gate receives the step description, its
invariants, the worker's own finish summary, and the raw verification
output — so the worker's claims are checked against the diff and the
test results, not taken on faith.

## Ground truth discovery

AiWrangler discovers `aiwrangler.config.json` from the gate directory
upward. seekr guarantees one exists in every run worktree:

- **Your repo commits one** — it is checked out in the worktree
  automatically, and your corpus (protocol spec, review rules,
  divergence rulings, open questions, plan doors) governs every run.
- **Your repo doesn't** — seekr writes a minimal generated config at the
  worktree root (default gates, `jev-1.13.0`, ledger and cache pointed at
  the run's state dir) and git-excludes it, so it never lands in diffs
  or on the branch. Standard checks — scope, claims, silent defaults,
  injection, test quality — still run; there is just no
  project-specific corpus.

## Human-in-the-loop

When the check gate returns HUMAN REVIEW, the step parks with status
`needs_owner` and the run continues independent steps. The owner flow:

```bash
seekr ack <run-id>                                   # list pending findings + diff hash
seekr ack <run-id> --rules RULE-10 --note "approved: trust boundary is intentional"
seekr resume <run-id>
```

Acknowledgments are recorded in AiWrangler's append-only ledger, void on
any diff change, and block-severity findings are never ackable.

## Egress and degradation

The semantic battery sends task/diff/spec text to `api.typesafe.ai`
(pinned to `jev-1.13.0`). Set `AIWRANGLER_EGRESS=off` for a
deterministic-only, zero-egress mode — expect DEGRADED verdicts, which
seekr treats fail-closed: completed steps cannot pass without the
semantic layer unless you explicitly pass `--allow-degraded`.

## Testing without tokens

`mock_aiwrangler` (shipped with seekr) is a scenario-driven stand-in for
the real server:

```sh
mock_aiwrangler                      # healthy PASS scenario, zero tokens
mock_aiwrangler scenario.json       # canned verdicts, e.g. forced FIX REQUIRED
```

The e2e test suite runs the entire governor loop against it.
