# Configuration

seekr reads `~/.config/seekr/config.toml`. Everything the governor loop
needs lives under `[jj]`; providers are shared across the app.

## Providers

```toml
[[providers]]
name = "qwen-local"              # referenced by [jj] roles
key = ""                         # or QWEN_LOCAL_API_KEY env
base_url = "http://server:11434/v1"   # any OpenAI-compatible endpoint
model = "qwen3.5:latest"
timeout = 300                    # optional, seconds per HTTP call
```

Key resolution order: `<NAME>_API_KEY` env → `SEEKR_API_KEY` env →
keyring → the `key` field.

## `[jj]` — the governor

| Key | Default | Meaning |
|---|---|---|
| `worker_provider` | active provider | local SLM that grinds steps |
| `frontier_provider` | none | planner + escalation tier; without it only `--plan` runs work |
| `max_attempts_per_step` | 3 | local attempts before frontier escalation |
| `max_frontier_calls` | 5 | hard ceiling on frontier calls per run |
| `verification_timeout_secs` | 600 | wall clock per verification command |
| `step_timeout_secs` | 3600 | wall clock per step (all attempts) |
| `worker_temperature` | 0.2 | worker sampling |
| `worker_max_tokens` | 8192 | worker reply budget |
| `worker_reasoning` | `"none"` | reasoning-effort hint; silences thinking tokens on Ollama models |
| `worker_read_lines` | 400 | read_file line window |
| `wrangler_command` | `"aiwrangler-mcp"` | how seekr launches the AiWrangler MCP server (argv, whitespace-split) |
| `wrangler_timeout_secs` | 300 | per-call gate round-trip timeout |
| `allow_degraded` | false | let runs proceed when the semantic gate is unreachable |
| `allow_web` | false | give the worker `web_fetch` (fetched content is fenced untrusted) |
| `allow_subagent` | true | give the worker read-only explorer subagents |

## `[agent]` — shell policy

`shell_blocklist` is a substring list applied to every command the
worker proposes and every verification command. The defaults block the
usual disk-shredding suspects; add your own.

## Environment

| Variable | Effect |
|---|---|
| `TYPESAFE_API_KEY` | powers AiWrangler's semantic battery |
| `AIWRANGLER_EGRESS=off` | deterministic-only, zero-egress gates |
| `AIWRANGLER_POLICY` / `AIWRANGLER_MODEL` | forwarded to AiWrangler |
| `SEEKR_WORKER_REASONING` | beats `[jj] worker_reasoning` |
| `SEEKR_STATE_DIR` | relocate run state (used by tests) |

## AiWrangler config

AiWrangler reads its own `aiwrangler.config.json` — discovered from the
run's worktree upward. If your repo commits one, its corpus (protocol
spec, review rules, divergence rulings, open questions) governs every
run against that repo. If not, seekr generates a minimal gate config
per run with the ledger under the run state dir, so gates are always
active. Thresholds and gate flags live in AiWrangler's config, not
seekr's — see the [AiWrangler docs](https://github.com/kodr-pro/AiWrangler).
